# Phase 1.4 — Real note generation

**Status:** done · **Date:** 2026-08-25
**Related decisions:** [0021](../decisions/0021-haiku-only-luna-dropped.md)
(Haiku-only, decided ahead of this phase — user's call), [0022](../decisions/0022-source-span-citation-design.md)
(source spans cite segment IDs, not model-emitted offsets — implementation)

## What changed

- **New** `app/services/note_generation/haiku.py:HaikuNoteGenerator` —
  the real implementation, replacing the `NotImplementedError` stub.
  Everything below hangs off the same forced-tool-call/structured-output
  approach the checklist named as the explicit ask (no free-text
  parsing).
- **`TranscriptSegment` gained an `id: str | None` field**
  (`app/services/asr/base.py`) — the stable citation target Phase 1.4
  cites *instead of* asking the model to count characters. `None` until
  persisted; `app/services/transcripts.py` assigns `"seg{i}"` at persist
  time and repopulates it on every load. This forced a small,
  order-sensitive fix in `_segments_to_json`: the explicit `"id"` key
  must be spread *after* `**dataclasses.asdict(segment)`, not before —
  otherwise the dataclass's own (usually `None`) `id` field silently
  overwrites the real assigned one, since dict literals resolve
  duplicate keys to the last one written.
- **`SourceSpan` redesigned** (`app/services/note_generation/base.py`) —
  an earlier, uncompleted stub used raw `transcript_start_ms`/`end_ms`
  timestamps. Replaced with `segment_ids: list[str]` plus
  `text_start`/`text_end` offsets into the *note's own text* (see
  decision 0022 for the full reasoning).
- **`GeneratedNote` gained `prompt_version: str`** (now required) and
  `source_spans_json()`, which serializes all four sections' spans and
  suppression flags into the JSON `Note.source_spans` already stores.
- **`Note.prompt_version`** — new nullable column
  (`b8c9d0e1f2a3_note_prompt_version.py`), stored on every generated
  note so "did we change the prompt?" is answerable from the data.
- **`app/tasks/pipeline.py:generate_note`** now persists
  `prompt_version` and `source_spans_json()` on the `Note` row it
  creates — previously it only wrote the four section texts.
- **`app/core/config.py`** — `anthropic_model` (default
  `claude-haiku-4-5-20251001`) and `note_generation_low_confidence_threshold`
  (default `0.5`) settings, plus matching `.env`/`.env.example` entries.
- **Mechanical suppression, two layers:** `_format_transcript` replaces
  any word below the confidence threshold with a literal `[INAUDIBLE]`
  in the prompt text — collapsing adjacent markers into one, since a
  run of unreliable words is one gap, not one marker per lost word — so
  the model is never shown the ambiguity to smooth over. Independently,
  the tool schema forces a `suppressed` boolean per section, and
  `_build_section` forces `text=""` whenever it's `true`, regardless of
  whatever sentences the model also emitted.
- **Citations verified, not trusted:** `_build_section` drops any
  `segment_id` the model cites that isn't one of the real IDs sent in
  that prompt — silently, and only the citation, not the sentence.
- **Tests:** new `tests/test_note_generation_haiku.py` (16 tests) —
  prompt formatting and marker collapsing, tool schema shape, tool-input
  extraction (including the "tool wasn't called" failure), span
  computation by concatenation, hallucinated-citation dropping,
  suppressed-forces-empty enforcement, the API-key gate, the
  empty-transcript no-API-call short circuit, a golden-transcript
  end-to-end case (mocked response in, exact `GeneratedNote` shape out,
  including a citation that gets scrubbed), HTTP-error propagation, and
  a real (un-mocked) httpx request-building check — the same category of
  test that caught a real bug in Phase 1.3's Groq integration.
- **Updated `tests/test_transcript_persistence.py`** for the new
  `TranscriptSegment.id` field: added a `_with_ids()` helper
  (`dataclasses.replace`) since the sample fixtures use `id=None` but a
  real persist/load round trip now assigns real IDs; fixed
  `_RecordingNoteGenerator.generate()` to pass the now-required
  `prompt_version`.

## How the pieces connect

```
load_transcript(db, encounter_id)
        │  (each TranscriptSegment carries its persisted "seg0", "seg1", ... id)
        ▼
HaikuNoteGenerator.generate(transcript)
        │
        ├─ empty transcript? → all-suppressed GeneratedNote, no API call (cost)
        │
        ├─ _format_transcript(transcript, threshold)
        │     → "[seg0 | speaker_unknown] word word [INAUDIBLE] word\n..."
        │       (low-confidence words replaced before the model ever sees them)
        │
        ├─ httpx.post(Anthropic /v1/messages,
        │              tool_choice={"type":"tool","name":"emit_note"})
        │     → forced structured output, one JSON shape, always
        │
        ▼
_extract_tool_input(response) → {assessment: {...}, plan: {...}, ...}
        │
        ▼
_build_section(raw, valid_segment_ids)   (per section, x4)
        ├─ suppressed=true  → text="", spans=[]            (mechanical override)
        └─ suppressed=false → concatenate sentences, tracking a cursor
                              for exact text_start/text_end; drop any
                              cited segment_id not in valid_segment_ids
        │
        ▼
GeneratedNote(assessment, plan, subjective, objective,
              provider="haiku", prompt_version="haiku-v1")
        │
        ▼
app/tasks/pipeline.py:generate_note
        → Note(..., note_generator_provider, prompt_version,
               source_spans=generated.source_spans_json())
```

The citation chain that makes the grounding UI (Phase 3, P0-7) possible
end to end: `transcripts.py` assigns segment IDs at persist time (this
phase's addition) → `haiku.py` hands those same IDs to the model in the
prompt → the model cites them back → `_build_section` verifies each
citation against the set actually sent → `source_spans_json()` persists
the verified result on `Note.source_spans`. Nothing in that chain trusts
an unverified claim from the model, and nothing asks the model to
produce a number (an offset, a timestamp) it would have to guess at.

## Tests

16 new tests in `tests/test_note_generation_haiku.py`; 5 assertions
updated across 3 tests in `test_transcript_persistence.py` for the new
`id` field and `prompt_version` requirement. Full suite: **107 passing**
(up from 91), `ruff` and `mypy` both clean.

## Notable follow-ups

- **Never run against a live Anthropic key**, same caveat every external
  integration in this codebase has carried before its real key existed
  (Groq's Whisper integration in 1.3 carried the identical caveat). The
  tool schema and prompt are real and tested against a hand-built
  response fixture matching Anthropic's documented tool-use shape, but
  should be confirmed against one real response before trusting this
  against real consults.
- **P0-4's diarization-dependent language ("map speaker roles") still
  has no real signal to work from** — Phase 1.3's ASR vendor (Groq
  Whisper) produces no speaker labels at all (decision 0018), so every
  segment handed to `HaikuNoteGenerator` is `speaker_unknown`. The model
  currently has to infer who's speaking from conversational content
  alone, with no labeled turns to lean on. This is the exact "materially
  harder job for the LLM" flagged as a carry-forward risk at the end of
  Phase 1.3 — nothing in 1.4 resolves it, and note quality (not just
  transcription quality) is where it would first show up.
- **Phase 1.5 (pipeline failure handling) is the natural next phase** —
  it's the only remaining item in Phase 1, and `generate_note`'s
  `except Exception: self.retry(...)` wrapper (already scaffolded) is
  what actually catches the HTTP errors this phase deliberately leaves
  uncaught.
