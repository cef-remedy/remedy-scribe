## The one thing to know first

The **script text is a placeholder written by an engineer.** The PRD lists
"Is the RA 4200 consent flow cleared by Philippine counsel?" as an Open
Question owned by Legal and marked **blocking — "recording feature cannot
launch without this"**. That question is still open.

So this phase delivers the *mechanism*: complete, tested, and demonstrable.
The wording is a draft, isolated in one file so counsel's version is a single
edit, and the app itself displays a banner saying it has not been cleared.
Nothing here should be read to a real patient yet.

## What changed

### The ordering, which P0-1 pins more tightly than it appears

My first reading of P0-1 was wrong in a way worth recording. I assumed the
doctor starts recording, reads the script, and the recorded asking becomes
segment 1. That satisfies the second bullet and **violates the first**, which
says nothing may be captured before consent exists.

The only sequence satisfying both: roster → read the script aloud → log the
outcome → *then* start recording → speak a short confirmation as segment 1.
Consequently **the consent screen never touches the microphone**, and there
is a smoke assertion for exactly that, because "no `getUserMedia` here" is
the sort of property that regresses invisibly.

### Backend

- **`storage.delete_object()`** — new. Returns a bool rather than raising: a
  withdrawal must not fail because S3 was briefly unreachable.
- **`consent.handle_withdrawal()`** — the server half of P0-1's withdrawal
  clause. Three actions ordered so the least important cannot undo the most:
  the ledger entry is committed first (it is the legal record), the retention
  clock is set to now (durable backstop), then an immediate delete is
  attempted (best-effort).
- **`POST /api/v1/consent`** now returns a withdrawal outcome for
  `withdrawn` events, so the client can tell the doctor what actually
  happened instead of guessing.

### Frontend

- **`lib/consent-script.ts`** — both language versions as data, plus the
  roster constants and the spoken-confirmation line. Deliberately not inline
  strings in components.
- **`routes/Consent.tsx`** — three steps: roster (RA 4200 needs every party
  named), script shown in both languages with the *spoken* one selected and
  recorded, then the decision. Decline is unreachable until the script has
  been advanced past — a decline is a response to the script, and logging one
  the patient was never read would claim informed refusal that did not happen.
- **Pause/resume in `RecordingSession`** — for mid-visit re-consent.
- **`routes/Record.tsx`** — routes into the consent flow when blocked, shows
  the spoken-confirmation prompt only while recording actually runs, and adds
  the pause and withdrawal controls.
- **`RecordingIndicator`** — a paused state that is visually distinct but
  still unmistakably a live session. A paused recorder that looks like no
  recorder is how someone gets recorded without realising it.

### Pause/resume is not as simple as calling `MediaRecorder.pause()`

Three interactions with 2.2's gap detection, each of which would have
produced a wrong reading:

1. **The worklet would keep counting samples the recorder is no longer
   writing**, so the pause would be reported as lost audio. Fixed by
   suspending the `AudioContext` too, stopping both clocks together.
2. **The stall detector would fire**, because worklet silence is its symptom
   — and during a deliberate pause that silence is expected. The monitor now
   skips stall and suspend detection while paused.
3. **The pause duration would read as a wall-clock jump**, i.e. a "system
   suspend" gap — the recorder logging a fault it caused itself. Both
   watchdog baselines are reset on resume.

Plus one that would have silently eaten audio: **a paused `MediaRecorder`
ignores `requestData()`**, so `stop()` resumes it first, then flushes. Without
that the buffered tail is discarded.

The smoke test asserts the outcome directly: `Paused 0:01` reported
separately, `Missing 0:00`.

```
                    │
        ┌───────────┴────────────┐
        ▼                        ▼
   "declined"                "given"
   ledger entry              ledger entry
        │                        │
        ▼                        ▼
  app fully usable      /record?confirm=1 ──► gate now open
  nothing captured               │
                                 ▼
                      Start recording ──► speak the confirmation
                                          (segment 1, P0-1)
                                 │
                ┌────────────────┼────────────────┐
                ▼                                 ▼
    "Someone joined — pause"          "Patient withdrew consent"
                │                                 │
     pause FIRST (compliance                stop capture
     action, no network wait)                     │
                │                          delete local chunks
     fresh "given" entry with                     │
     the new roster                        POST withdrawn
                │                                 │
     resume ONLY if the ledger              server: retention→now,
     write succeeded                        delete object, pipeline

```

## Verification

**API: 143 passing** (up from 136 — 7 new withdrawal tests), `ruff` and
`mypy` clean.

**Web: 18 unit tests**, `tsc` clean, production build fine.

**End-to-end: 35/35** (`smoke/consent-flow.cjs`, real Chromium, live API).
Every check maps to a P0-1 clause:

| | |
|---|---|
| Blocked screen routes into the consent flow | pass |
| Warns the script is not cleared by counsel | pass |
| Decline **not** offered before the script is presented | pass |
| Both languages present, with real Filipino and English text | pass |
| Required participants locked, not optional | pass |
| **Microphone never touched on the consent screen** | pass |
| Decline → ledger `declined`, still blocked, app usable | pass |
| Grant → ledger `given`, `script_language` recorded, gate opens | pass |
| Spoken-confirmation prompt shown once recording runs | pass |
| Pause → indicator switches to paused and stays visible | pass |
| Resume gated behind the fresh ledger entry | pass |
| Second `given` entry appended for the new roster | pass |
| **Paused time reported separately, not as missing audio** | pass |
| Withdrawal → 3 local chunks → 0 | pass |
| Withdrawal wording says "next stage boundary", not "instantly" | pass |
| Ledger `withdrawn`, recording blocked again | pass |

The decline path runs on its **own encounter**, because the ledger is
append-only — a decline followed by a grant on the same encounter leaves
consent valid and would have proven nothing.

## Decision 0003, closed by elimination

Open since Phase 0.1. It offered manual flagging vs. ASR-diarization
detection of a new speaker. **Decision 0018 removed the second option
entirely** — Groq Whisper has no diarization capability at all, so there are
no speaker labels for it to read. Manual flagging is not the preferred
option; it is the only implementable one.

Worth stating plainly: the original concern is unaddressed. A doctor
mid-examination may simply forget to flag, and nothing will catch it. What
the design does instead is make remembering cheap and the state honest — the
pause happens before any network call, and resuming is gated on the ledger
write rather than the doctor's word.

## Open follow-ups

- **Legal clearance is blocking.** Not an engineering task, but it gates the
  whole feature. The mechanism is ready for counsel's text.
- **A ledger timestamp tie is undefined.** `current_consent_state` folds by
  `created_at`; identical timestamps make the consent state
  non-deterministic. Unrealistic over HTTP, but bad for a fold answering a
  legal question. Cheap fix: a monotonic sequence column. Recorded in
  decision 0027; found because a test fixture offset timestamps the wrong
  direction and flipped a withdrawal behind a grant.
- **The patient's own spoken "yes" is not on the recording** — only the
  doctor's confirmation that consent was given. Capturing the former means
  recording before consent is logged, which contradicts P0-1's first bullet.
  Someone with authority has to decide that, not engineering.
- **No end-of-recording roster confirmation.** The obvious cheap mitigation
  for a forgotten mid-visit flag: ask the doctor to confirm who was present
  before the note is filed. Cannot pause anything retroactively, but would
  surface a disclosure the ledger otherwise never gets.
- **Withdrawal deletes local chunks but nothing uploads yet** (2.4), so the
  server-side delete path is currently only exercised by tests with a
  synthetic `audio_object_key`.
