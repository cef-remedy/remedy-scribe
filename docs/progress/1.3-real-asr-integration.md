# Phase 1.3 — Real ASR integration

**Status:** done · **Date:** 2026-08-25
**Related decisions:** [0018](../decisions/0018-groq-whisper-instead-of-elevenlabs-scribe.md)
(vendor switch, **diarization lost** — user's call), [0019](../decisions/0019-asr-quality-validation-plan.md)
(quality validation plan — user's call)

## The vendor switch (user's call) — read this first

The PRD (`remedy-scribe-prd.md`, P0-3) names ElevenLabs Scribe v2 "with
speaker diarization enabled" explicitly. This phase implements **Groq-
hosted Whisper large-v3** instead, per direct instruction. This is not a
drop-in replacement: **Whisper has no diarization capability at all** —
not weaker diarization, none. Every consequence of that is documented in
decision 0018; the short version is that 1.3's own "map speaker_0/
speaker_1 to doctor/patient" heads-up no longer applies, because there
are no speaker labels to map. That problem either gets solved with a
separate diarization component later, or pushed into Phase 1.4's note
generation inferring roles from conversational content alone — a
materially harder job for the LLM.

## What changed

- **Deleted** `app/services/asr/elevenlabs.py`. **New**
  `app/services/asr/groq_whisper.py:GroqWhisperProvider`.
- **`app/services/storage.py`** — new `download_object(key) -> bytes`,
  needed to fetch audio for the ASR call (storage.py previously only had
  upload-side operations).
- **`app/services/asr/base.py`** — `ASRProvider` gained `provider_name`
  (1.2) and now `model_version` (a property where the model is
  operator-configurable, like Groq's).
- **`Transcript.asr_model_version`** (new column + migration) — decision
  0017 (Phase 1.2) deferred this exact column until a real ASR
  integration existed to report a real version string; this phase is
  that integration, so it's added now.
- **Turn order, addressed structurally, not patched:** the original bug
  (`_parse_response` grouping every word by speaker across the *whole*
  recording) can't recur here — Whisper never groups by speaker in the
  first place, so there's no speaker-grouping step to get wrong. What
  `GroqWhisperProvider._parse_response` actually does is bucket Groq's
  flat, chronological `words` array into the `segments` array's time
  ranges, consuming both arrays strictly in order (`word_index` only
  moves forward) — turn order is preserved *by construction*, not by
  re-sorting after the fact.
- **Every segment/word is labeled `UNKNOWN_SPEAKER`** (`"speaker_unknown"`
  — deliberately not styled like Scribe's real `speaker_0`/`speaker_1`,
  so nothing downstream mistakes "no diarization happened" for
  "diarization succeeded with one speaker").
- **Per-word confidence is an approximation, documented as one:**
  Whisper's `verbose_json` exposes `avg_logprob` per *segment*, not a
  real per-word score. `_confidence_from_avg_logprob` converts it
  (`exp(avg_logprob)`, clamped to `[0, 1]`) and applies it uniformly
  across a segment's words — defaults to a neutral `0.5`, not a
  confident-looking `1.0`, when missing, since Phase 1.4's silence/
  low-confidence suppression logic will read this value.
- **Rate limits/timeouts/partial failures**: the provider raises real
  exceptions (`httpx.HTTPStatusError`, timeouts) and does not catch them
  — they propagate into `transcribe_encounter`'s existing
  `except Exception: self.retry(...)` wrapper, exactly as the checklist
  asks ("already scaffolded via `self.retry`").
- **Tests:** `tests/test_groq_whisper.py` (14 tests) — the word-bucketing/
  turn-order logic against a hand-built fixture matching Groq's
  documented `verbose_json` shape, trailing-word handling, confidence
  approximation, the API-key gate, a mocked full `transcribe()` call, and
  an HTTP-error-propagates-uncaught test. Updated
  `tests/test_transcript_persistence.py` for the new `model_version`
  field.

## How the pieces connect

```
GroqWhisperProvider.transcribe(audio_object_key)
        │
        ├─ storage.download_object(key)          → raw audio bytes
        ├─ httpx.post(Groq /audio/transcriptions) → verbose_json
        │    {segments: [...], words: [...]}   (both chronological)
        ▼
_parse_response: walk `segments` in order; for each, consume `words`
  from where the previous segment left off, up to that segment's `end`
  time — O(n) overall, order preserved because nothing is re-sorted
        │
        ▼
list[TranscriptSegment]  (speaker=UNKNOWN_SPEAKER throughout)
        │
        ▼
persist_transcript(..., provider_name="groq_whisper_large_v3",
                    model_version=settings.groq_whisper_model, ...)
```

## Tests

12 new tests in `tests/test_groq_whisper.py`; 2 tests updated in
`tests/test_transcript_persistence.py` for the new field. Full suite: 90
passing.

## Notable follow-ups

- **The diarization gap is the headline item to carry forward.** Decision
  0018 lists three options if Phase 1.4's note quality suffers without
  speaker labels: a separate diarization pass, a different ASR vendor,
  or LLM-inferred roles from undiarized text. No action taken yet — this
  is explicitly a "wait and see what alpha shows" call, not a resolved
  one.
- **Decision 0019's validation plan is scoped correctly, not skipped:**
  the user's planned two-person-audio test is genuinely useful for
  transcription *accuracy* (especially on Taglish code-switching) but
  cannot reveal speaker-differentiation, because the model has no
  mechanism for that at all — this is set as an expectation up front so
  the test's result (almost certainly "no speaker separation, ever") is
  read correctly rather than as a surprising failure.
- This provider's real HTTP call has never run against a live Groq API
  key in this environment — `_parse_response` is real and tested against
  a documented fixture, but the fixture's exact field names should be
  confirmed against one real response before trusting this in
  production, same caveat the ElevenLabs stub carried before it.
