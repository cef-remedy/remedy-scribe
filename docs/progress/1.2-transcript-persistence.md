# Phase 1.2 — Transcript persistence

**Status:** done · **Date:** 2026-08-25
**Related decisions:** [0016](../decisions/0016-transcript-storage-shape.md)
(storage shape — user's call on JSONB), [0017](../decisions/0017-transcript-scope-boundary-with-phase-1.3.md)

## The 🧠 decision (user's call)

**Where does the transcript live?** Decided: a Postgres column holding
the whole structure as encrypted JSON (the checklist's "JSONB" option) —
not a row-per-word table, not object storage alongside the audio.

## Why this was next

Two places in the pipeline already claimed to handle this and didn't:
`transcribe_encounter` computed `segments` and discarded them
(`_ = segments`); `generate_note` always called the note generator with
`transcript=[]`. Nothing connected the two Celery tasks in the chain —
the second one had no way to see what the first one produced.

## What changed

- **New `app/core/security.py:EncryptedJSON`** — a `TypeDecorator`
  alongside `EncryptedString`: JSON-serialize, then Fernet-encrypt, into
  a `Text` column. Refactored both encrypted types to share one
  `_fernet_from_settings()` helper instead of duplicating the
  "raise if the key is unset" logic.
- **New `app/models/transcript.py:Transcript`** — one row per encounter
  (`encounter_id` unique + indexed), `asr_provider` (string), `segments`
  (`EncryptedJSON`), `retention_expires_at` (mirrors the audio's policy).
- **New `app/services/transcripts.py`** — `persist_transcript` (upserts
  on `encounter_id`) and `load_transcript` (returns `[]` if nothing's
  been persisted yet, matching `generate_note`'s old default). These are
  the only place that knows how to convert between
  `ASRProvider`'s dataclasses (`TranscriptSegment`/`TranscriptWord`) and
  the JSON shape stored on disk — neither Celery task needs to know that
  shape exists.
- **`app/services/asr/base.py`** — added `ASRProvider.provider_name`
  (class attribute), set to `"elevenlabs_scribe_v2"` on
  `ElevenLabsScribeProvider` — the minimum needed for a persisted
  transcript to record what produced it (see decision 0017 for why
  `asr_model_version` isn't added yet).
- **`app/tasks/pipeline.py`** — `transcribe_encounter` now calls
  `persist_transcript(...)` instead of `_ = segments`; `generate_note`
  now calls `generator.generate(transcript=load_transcript(db, encounter_id))`
  instead of `transcript=[]`.
- **Alembic migration** for the `transcripts` table.
- **`tests/test_transcript_persistence.py`** — 9 tests: round-trip
  fidelity, upsert-not-duplicate, stable per-segment IDs, the encryption
  guarantee (raw-column check + isolated `EncryptedJSON` round trip),
  the retention clock, and both Celery tasks wired end-to-end with
  fakes standing in for the still-stubbed ASR/LLM providers.

## How the pieces connect

```
ASRProvider.transcribe()                    NoteGenerator.generate()
  → list[TranscriptSegment]                   ← list[TranscriptSegment]
        │                                            ▲
        ▼                                            │
persist_transcript(db, encounter_id, ...)    load_transcript(db, encounter_id)
        │                                            │
        └──────────────► Transcript row ◄────────────┘
                          (segments: EncryptedJSON)
```

`app/services/transcripts.py` is the seam: `transcribe_encounter` and
`generate_note` run as two separate Celery tasks in a chain, with no
shared memory between them — the `Transcript` row *is* the handoff.
Neither task needs to know the storage format; they only deal in
`TranscriptSegment`/`TranscriptWord`, the same dataclasses the ASR/note
layers already used before this phase.

## Tests

9 new tests in `tests/test_transcript_persistence.py`; full suite: 78
passing (69 from before + 9 new).

## Notable follow-ups

- Decision 0016: the addressable unit stored is the ASR **segment**
  (currently one speaker-diarized turn), not a sentence — my own earlier
  conversational framing said "sentence," but nothing in the pipeline
  produces sentence boundaries yet, and Phase 1.3's turn-grouping bug
  means even "segment" doesn't mean quite what it should today. Nothing
  is lost: `words`' own timings let a future sentence-splitter re-derive
  finer units without a migration.
- Decision 0017: `asr_model_version` deliberately not added yet — there's
  no real ASR API call to report a real version string from. Phase 1.3
  adds it alongside wiring the actual ElevenLabs integration.
- Access logging for transcript *reads* isn't wired — there's no read
  endpoint yet for a human or route to trigger one. Deferred until Phase
  3 (grounding UI) or 4.2 (audit sweep) actually add a consumer.
