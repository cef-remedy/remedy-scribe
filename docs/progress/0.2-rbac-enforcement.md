# Phase 0.2 — Actually enforce RBAC

**Status:** done · **Date:** 2026-08-25 · **Commit:** `e9a8602`
**Related decisions:** [0004](../decisions/0004-note-read-access-scope.md),
[0005](../decisions/0005-rbac-role-policy-and-audit-log-endpoint.md)

## Why this was next

`require_role(...)` was defined in `app/api/deps.py` and attached to
**zero** routes — `models/clinician.py`'s docstring claimed role "drives"
access control, but nothing read `Clinician.role` anywhere in the request
path. A dependency that's written but never attached is worse than one
that doesn't exist: it reads like coverage in review and provides none.

## What changed

- **Clinical write routes now require role `"doctor"` specifically** (not
  `"admin"` — see decision 0005 for why those aren't interchangeable):
  `POST /consent`, all four `encounters.py` routes (start/resume, loose
  list, link-patient, confirm-upload), both `patients.py` routes
  (match, create), and `notes.py`'s `PATCH /{id}` + `POST /{id}/transition`.
- **`GET /notes/{id}` stays open** to any authenticated clinician regardless
  of role — no `require_role`. Need-to-know is enforced by making every
  read accountable (the pre-existing `audit.record` call on every read),
  not by blocking it. See decision 0004 for the reasoning (colleague
  coverage, prior-visit context).
- **New `app/api/routes/audit_logs.py`** (`GET /audit-logs`), restricted to
  `compliance`/`admin`. This endpoint didn't exist before — added now,
  ahead of Phase 4.2's full review interface, because 0.2's own required
  test ("a doctor token must not be able to read the audit log") needs a
  real endpoint to fail against.
- **`tests/test_rbac.py`** — 9 tests: the two negative cases the checklist
  names explicitly (compliance can't `PATCH`/sign a note; doctor can't
  read audit logs), plus a positive control per route so a future
  refactor that accidentally makes everything 403 gets caught too.

## How the pieces connect

```
Clinician.role ("doctor" | "compliance" | "admin")
        │
        ▼
require_role(*roles)  ── app/api/deps.py, defined since before this
        │                 phase, attached to zero routes until now
        ├── wraps get_current_clinician (JWT "sub" → fresh DB lookup)
        │   checks the DB row's role, NOT the JWT's role claim — a role
        │   change takes effect on the clinician's next request, not
        │   their next login
        ▼
Route dependency: Depends(require_role("doctor"))  →  403 if mismatched
```

The key mechanical fact: `get_current_clinician` re-fetches the
`Clinician` row from the DB on every single request rather than trusting
the JWT's embedded `role` claim. That's what makes role changes
effective-immediately rather than stale-until-re-login.

## Tests

9 new tests in `tests/test_rbac.py`; full suite (27 tests at this point)
passing on SQLite.

## Notable follow-ups

- Decision 0004 (open note reads) is a real product/compliance tradeoff,
  not a settled fact — flagged as revisitable if Remedy's DPO/counsel
  wants per-record read restriction, or if the audit log itself ever
  surfaces a doctor browsing outside their care relationship.
- The audit-log endpoint added here is intentionally minimal (no
  filtering, pagination, or retention policy) — Phase 4.2 owns the real
  review interface.
